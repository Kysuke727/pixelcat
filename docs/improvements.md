# 可以改进的地方（2026-11-17 整理）

这份清单来自对项目的实际检查（代码、测试、渲染截图、模拟排查），不是凭印象列的。每条都写了依据，以及我建议的做法。标记：**【高】** 会影响玩家或有风险，**【中】** 值得做，**【低】** 以后再说。

## 一、会影响玩家的问题

1. **【高】成长面板里的“技能点”已经没有任何效果。**
   - 依据：`get_skill_modifiers()` 在整个项目里没有任何地方使用（只有定义）；减速/连接/束缚/绕圈对应的是已经删除的旧毛线玩法。但成长面板（P 键）仍然让玩家把点数加到这些技能上。
   - 后果：玩家花了点数却什么都没发生。
   - 建议：去掉这部分界面，面板改成显示“已学会的招式”；已有存档里的 `skill_points` 要兼容（读出来忽略或折算成属性点）。

2. **【高】F3 调试面板在正式发布的版本里也能打开**（能加血、加经验、解锁全部招式）。
   - 依据：`debug_panel.gd` 只判断了按键，没有判断是否调试版本。`scenes/dev/` 的试玩入口同理。
   - 建议：只在 `OS.is_debug_build()` 时启用。

3. **【高】主菜单的“图鉴”和“设置”按钮没有任何功能。** `main_menu.gd` 只接了“继续游戏”“再开一局”“退出游戏”。
   - 建议：先隐藏，或者做一个最小的设置页（音量、画面效果开关）。

4. **【高】夜晚的战斗面板又大又挡视野**，并且和小鱼干计数重叠。截图里能看到左上角一大块被遮住。
   - 建议：做成紧凑的像素风（参考白天的状态条）：血、护盾、冲刺各一小条，招式提示放到屏幕底部。

5. **【中】小树林看起来像白天**，没有夜晚的感觉。路灯只是摆设，不发光。
   - 建议：整体压暗，路灯发光，加一点萤火虫和雾。这是让它“像夜晚森林”最有效、最省事的一步。

6. **【中】史莱姆追人是直线走，在树墙边可能被卡住。** 我没有实际验证，是看代码的判断。
   - 建议：先写一个模拟测试确认，再决定要不要加简单的绕障（沿墙滑动或寻路）。

7. **【中】难度和手感还没有人试玩验证。** 比如：中央空地 4 只同时、死亡丢一半物品、接触史莱姆 35% 滑倒/黏住、绕背 50% 暴击、冲刺 2 次充能。这些数值都集中在 `scripts/combat_v3_tuning.gd`，试玩后改起来很快。

## 二、内容

8. **【中】敌人只有一种。** 植物史莱姆的美术已经有了（`assets/characters/plant_slime/`）但没有被用上。建议做成会吐弹的远程怪，再加分裂、带盾、冲锋，最后一个小 boss（设计文档第 6 节阶段 4）。
9. **【中】小树林缺少探索回报。** 除了老树洞，没有别的东西值得绕路。右下角那一大片空树林可以开一个隐藏角落（放材料、小鱼干），再加几个地标（倒下的树、蘑菇圈、石头圈）帮助认路。
10. **【中】生命药水没有实际效果**（使用时提示“这件物品目前还不能使用”）。更多合成配方你说过后面再做。
11. **【中】合成还没有和战斗接起来。** 现在合成只能做毛线球和逗猫棒（加心情），变强的方式只有升级。建议让材料能做出爪套、项圈这类装备，改变招式效果。
12. **【低】白天世界太小**（你提过）。需要和夜晚共用同一套“跟随镜头”。
13. **【低】第二、第三张地图**（你说先把第一张做完）：第 2 张放扑击，第 3 张放反击爪。

## 三、手感和反馈

14. **【高】大部分新动作没有音效**：冲刺、闪避、完美闪避、扑击、暴击、滑倒、黏住、学会招式、结算、选图、拾取。目前只有敌人的攻击/受击/死亡声和你朋友做的合成音效。
    - 建议：和合成界面一样，给每个动作留音效槽，让音乐同学直接拖文件进去。同时建立 SFX / 音乐 / 界面 三条音频总线，设置里可以分别调音量。现在没有总线。
15. **【中】效果开关没有界面。** 顿帧、震屏、粒子、伤害数字都已经有开关变量（`HitFeel`），只是没有设置页可以点。这对容易晕的玩家很重要。
16. **【中】没有新手提示。** 新玩家不知道 J/K/空格/Shift 分别干什么，也不知道完美闪避和绕背暴击。可以做一个第一次进夜晚时的简短提示，或在暂停菜单里放按键表。
17. **【低】不能改键、没有手柄支持。**
18. **【低】死亡时的演出很简单**：只有 0.8 秒的停顿和结算画面。

## 四、代码和工程

19. **【中】仓库里没有 README，也没有 CLAUDE.md。** 新来的人（包括你朋友）看不到“这个项目是什么、怎么跑、怎么测试”。`docs/how-to-play.md` 只讲怎么试玩。
    - 建议：加一个简体的 README.md（项目介绍、运行方法、目录说明、测试方法）；加 CLAUDE.md 写明约定（仓库里的文字用简体、改完要跑哪些测试）。
20. **【中】没有自动测试（CI）。** 现在 38 个测试要手动跑，整套大约 **5 分钟**。建议加 GitHub Actions：每次推送自动下载 Godot 4.7 跑测试，红了就能马上知道。
21. **【中】没有导出配置（`export_presets.cfg`），没有 Windows 版本可以直接发给朋友玩。** 要导出需要 Godot 的导出模板（较大，需要下载）。想让别人不装 Godot 也能试玩的话，这件事值得做。
22. **【中】几个文件太大**：`progression_manager.gd` 837 行、`slime.gd` 822 行、`cat_controller.gd` 746 行、`player_combat.gd` 648 行、`crafting_ui.gd` 509 行。建议把 `cat_controller` 里的冲刺/扑击/滑倒/黏住拆成独立组件，把 `progression_manager` 里的存档读写拆出去。
23. **【低】界面里混着游戏逻辑**：`ui_main.gd` 里有“饥饿/心情/精力随时间下降”的计算，应该放到 `CatStats` 或 `DayManager`。
24. **【低】测试靠环境变量 `PIXELCAT_TEST_MODE` 来关掉随机效果。** 可以收成一个统一的测试模式开关，更不容易漏。
25. **【低】测试依赖 `tools/data/forest_grove_level.json`**（开发工具生成的数据）。以后如果发布时裁掉 `tools/`，这个测试会找不到文件。
26. **【低】没有许可证文件（LICENSE）。** 如果以后公开仓库，需要想清楚用什么许可（音乐/字体各有自己的授权，`assets/audio/audio_license.txt` 已经在记）。

## 五、我建议的做法（三选一，或组合）

- **A：让朋友能直接玩到**（最快有成就感）：隐藏无功能按钮、关掉发布版调试面板、写 README、配置 Windows 导出。做完你可以发一个 exe 给朋友。
- **B：把第一张地图做完整**：夜晚光影 → 战斗面板改紧凑 → 探索回报和地标 → 史莱姆绕障 → 音效槽。做完后第一张图是一个完整、好看、好玩的关卡。
- **C：先试玩再调**：你玩一轮，把感受告诉我，我按你的感受调数值。成长面板的死技能点、新手提示穿插着做。

我的推荐：**先 C，再 B，A 穿插**。因为手感类的数值只有你玩过才知道对不对，而第 1、2 条（死技能点、发布版调试面板）很小、风险又高，可以马上顺手修掉。
